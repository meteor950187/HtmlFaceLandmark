## Context

`face4.html` 目前已經整合 FaceLandmarker 偵測、步驟式動作驗證、側錄蒐集、Blob 建立與播放詢問彈窗。對 demo 而言，主要問題不是功能缺漏，而是展示層訊息不夠集中，包含開始畫面語意、步驟進度感、完成狀態可理解性、播放詢問彈窗的產品感，以及左上角檢測資訊區過於像主視覺。

這次變更僅針對單頁 UI 收尾，且使用者已明確要求不要改動核心命名與責任分工，特別是 `recordedChunks`、`processingChunks`、`mediaRecorder`、`recorderStop()`、`setDetectProcess()`、`setNextStep()`、`setSuccessToTop()`、`API_FaceValidateChecked()`。因此設計必須把所有調整限制在文案、樣式、DOM 結構的最小必要範圍內。

## Goals / Non-Goals

**Goals:**
- 讓 demo 首屏、步驟區、完成畫面與播放詢問彈窗更容易理解，提升展示品質。
- 明確區分主要互動資訊與 debug 資訊，避免技術數值搶走主視覺。
- 將中文文案、字型與視覺語氣統一，避免 demo 呈現不一致。
- 定義一套完整 e2e 驗收故事線，覆蓋載入、檢測、完成、播放與取消播放。
- 保持現有錄影、Blob 建立與臉部偵測行為不變。

**Non-Goals:**
- 不調整 FaceLandmarker 門檻、步驟條件、錄影格式或 Blob 產生方式。
- 不改寫播放架構，不新增另一套 recorder / player state machine。
- 不把單頁 demo 重做成大型 redesign，也不引入新框架或外部依賴。
- 不重新命名或拆分既有核心函式與資料結構。

## Decisions

### 1. 以「展示層優先級」收斂變更範圍
採用三層優先級來控制改動：
- 必做：完成畫面語意、步驟進度感、播放彈窗文案與狀態。
- 可選：開始畫面展示感、debug 區弱化、字型與中文一致性。
- 不碰：FaceLandmarker 主流程、錄影與 Blob 主流程、舊 API 流程。

這樣的好處是能明確限制實作只在 UI polish，而不是擴散成核心重構。

替代方案：
- 直接重新設計整個畫面層級。未採用，因為風險高且違反最小侵入目標。

### 2. 沿用現有 DOM 與函式入口，只做最小必要擴充
開始畫面、步驟區、完成畫面與播放彈窗都已存在對應 DOM 區塊，因此後續實作應優先修改既有區塊的文案、樣式與少量結構，而不是再建立平行的畫面元件。

對播放流程的要求也相同：沿用 `setSuccessToTop()` 作為完成入口，沿用 `recorderStop()` 的既有責任，僅在展示層增加更清楚的等待與完成狀態。

替代方案：
- 建立新的播放面板、播放控制器與狀態變數。未採用，因為會把單純的 polish 變成架構改寫。

### 3. 將左上角檢測資訊區定義為 debug 資訊
`steps-detect-testInfo` 對展示者和開發者有用，但不應與主要步驟指示競爭注意力。設計上應將其視為次要資訊，透過尺寸、透明度、對比或預設顯示策略弱化其存在感。

替代方案：
- 完全移除檢測資訊區。未採用，因為 demo 調校與展示時仍可能需要這些資訊。

### 4. e2e 採用「demo 故事線」而非函式驗證
因為本頁核心價值在完整展示流程，最終驗收應以使用者路徑為中心：

```text
載入頁面
  -> 開始畫面
  -> 啟動相機
  -> 依序完成步驟
  -> 顯示完成畫面
  -> 跳出播放詢問
  -> 等待側錄整理
  -> 播放成功 / 取消返回
```

這比單點測 `recorderStop()` 或單一 step 更能反映 demo 是否可展示。

## Risks / Trade-offs

- [UI polish 侵入核心流程] -> 明確規定只可修改文案、樣式與最小必要 DOM 結構，禁止重構核心函式與命名。
- [完成畫面或彈窗調整後遮住播放畫面] -> 實作時需驗證 overlay 顯示與隱藏時序，避免完成遮罩與播放區互相覆蓋。
- [步驟進度資訊過多，反而降低可讀性] -> 優先採用簡單的步驟編號或進度點，不加入複雜說明。
- [debug 資訊弱化後影響調試] -> 僅調整視覺層級，不移除資料來源與更新邏輯。
- [手機直式畫面排版在 polish 後破版] -> e2e 驗收需包含窄螢幕與直式場景。

## Migration Plan

1. 先完成 UI polish proposal 所定義的必要項目，不變動核心邏輯。
2. 以單頁靜態檢查確認中文文案、步驟區、完成畫面與彈窗狀態沒有衝突。
3. 在目標瀏覽器進行完整 demo e2e 驗收。
4. 若播放或步驟流程出現回歸，優先回退 UI 層改動，不動 recorder / blob / face detect 主流程。

## Open Questions

- 完成畫面是要維持整片可點擊區塊，還是改成卡片式語意更強的視覺容器。
- 步驟進度感最終採用文字編號還是進度點，需依實際畫面密度決定。
- 左上角 debug 區是否預設顯示，或只在需要調試時顯示。
