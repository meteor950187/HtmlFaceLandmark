# 單頁人臉動作分析與側錄 Demo 設計提案

狀態：使用者已確認時間不變、PC 限寬方式由實作者處理、完成後用成功彈窗提供 Blob 側錄下載。已依此範圍實作並完成受控瀏覽器驗證；實體攝影機及 iOS／Android 實機待確認。

## 目的

將原本配合其他系統使用的頁面整理為可獨立操作、適合面試展示的單頁 Demo。核心展示是 MediaPipe WebAssembly 人臉特徵分析、分數驅動的動作互動，以及 MediaRecorder 側錄與 Blob 影片產出。後端真人／身份比對不在本次實作範圍。

## 方案

- 建議：沿用既有全螢幕相機與步驟引導，只調整開始、結束介面與必要的流程問題。維持單檔，變更幅度符合「些微修改」。
- 備選：在相機旁建立常駐技術說明側欄，方便面試時講解，但會縮小手機的操作空間並增加版面改動。

使用者已指定保留手機操作形式；PC 以左右黑底及中間限寬的直向畫面支援展示，不新增常駐側欄。

## PC 與手機版面

- PC 左右以黑色背景填滿，中間置中呈現原本手機式操作畫面。
- 中央畫面建議最大寬度 480px（實作預設值），窄視窗及手機使用可用的全部寬度。
- 高度依可視視窗調整，使用動態視窗高度；影片、遮罩、步驟及完成畫面均以中央容器為定位範圍。
- 不強制固定手機長寬比；短視窗允許介紹與完成內容在容器內捲動，維持按鈕可操作。

## 開始畫面文案（初稿，以下由精簡版取代）

標題：瀏覽器端人臉動作分析與側錄

說明：透過攝影機取得即時影像，使用 Google MediaPipe Tasks Vision 的 WebAssembly 執行環境，以 FaceLandmarker 分析人臉特徵與動作分數，並將測試過程錄製為可預覽、下載的影片。

三項展示重點：

1. WebAssembly 即時分析：整合 MediaPipe FaceLandmarker，於瀏覽器取得人臉特徵與眼部動作分數。
2. 分數驅動的互動：動作分數達到固定門檻後啟動過關提示，顯示目前步驟與進度。
3. 瀏覽器側錄與匯出：使用 MediaRecorder 蒐集攝影機串流，完成後產生 Blob 影片供預覽、下載，作為後端比對的影像輸入。

操作說明：允許使用攝影機後，依序完成臉部偵測、向右看、向左看及向下看。請保持光線充足，讓臉部位於畫面中央。

資料說明：測試影片僅暫存於此分頁，請在離開頁面前下載。

主要按鈕：開始測試

提示以「看向某方向」對齊現有眼部 blendshape 判斷，避免把眼球方向分數描述為頭部角度辨識。

## 互動流程

1. 頁面載入只顯示介紹，不開相機、不錄影。
2. 點擊開始後，顯示相機／模型準備狀態，避免重複開始；準備完成才進入測試並開始錄影。
3. 沿用四步測試與現有分數門檻：偵測到臉、左右各 0.45、向下 0.65。依使用者指示保留單次達標即可觸發的寬鬆行為，不要求連續達標或中斷重算。觸發後的等待維持現有 2000ms，不縮為 1 秒。
4. 保留步驟進度；最後一步的原有成功過場完成後，自動開啟成功彈窗並停止錄影，等待最後的 dataavailable 與 stop 事件後建立 Blob，並釋放相機。
5. 彈窗共用同一份 Blob 提供預覽與下載；關閉彈窗保留完成畫面，可以再次開啟下載。重新測試使用頁面重新載入，以清除原有資料並於離開時釋放舊 Object URL。

### 已核對的現有過場時間

工作區、HEAD 及 origin/main 對應提交的程式均設為：觸發達標後等待 2000ms，成功畫面顯示 2500ms 後才進下一步。成功光暈動畫為 1 秒；成功文字延遲 1 秒後淡入 1 秒，再於第 2 秒開始淡出 0.5 秒。現有完整過場因此為 2.5 秒。此提案保留現有過場，不額外調整時間。

## 工程範圍與限制

- 保留原生 HTML／CSS／JavaScript、既有 MediaPipe 版本與單頁架構。
- 保留既有核心函式名稱及資料容器，僅在此 Demo 所需範圍調整責任與時序；先前 UI polish 文件的「不改核心流程」限制描述的是舊變更範圍，本次包含錄影停止修正。
- 支援桌機滑鼠、鍵盤與手機觸控，使用語意化按鈕及 click 事件。
- 為相機拒絕授權、模型載入失敗、錄影格式不支援提供可閱讀的錯誤及重試方式。
- 移除不存在的 ExceptionMessage.js 引用；舊系統 API 函式保留原名但不會在此 Demo 的完成流程呼叫。
- 不新增後端、登入、上傳、照片／影片防偽分類或身份比對。
- 更新 README 與驗收清單，保留工作區既有未提交修改。
